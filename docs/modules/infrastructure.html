Infrastructure

Every side effect behind a small interface: GitBucket REST, git, Copilot, child processes, the work folder, SQLite, logs and costs. No business decisions live here.

On this page:PurposeComponentsFlow 1: prepare a clean cloneFlow 2: running a child processBusiness rules and edge casesDependencies

Purpose

The Infrastructure/ folder is the only place that talks to the outside world. Each capability has an interface, so jobs and the planner can be tested with fakes (tests/AiRunner.Tests/Fakes/). A GitBucket or CLI quirk is fixed in exactly one class (CLAUDE.md). No decision about "what should happen" is made here.

Flow 1: prepare a clean clone

  1. Clone path: work/<owner>/<name> next to repos.yml (Workspace.cs:32-33). The remote URL is {baseUrl}/git/{repo}.git (GitClient.cs:49).
  2. git clean -fdx deletes ignored files too, which is why commands.setup must reinstall dependencies for every job.
  3. The runner's own files (context.md, plan.md, PR_BODY.md, fix.md, diff.patch, changed-files.txt, review-fix.md, REPLY.md, .ai-workflow/) are listed in .git/info/exclude, so git add -A never commits them (Workspace.cs:28-30, 54-56).

How git gets its credentials

GIT_TERMINAL_PROMPT=0
GIT_CONFIG_COUNT=6
GIT_CONFIG_KEY_0=http.extraHeader     GIT_CONFIG_VALUE_0=Authorization: Basic base64(login:secret)
GIT_CONFIG_KEY_1=credential.helper    GIT_CONFIG_VALUE_1=            (empty: never ask the Windows credential store)
GIT_CONFIG_KEY_2=core.hooksPath       GIT_CONFIG_VALUE_2=work/.no-hooks   (a folder that does not exist)
GIT_CONFIG_KEY_3=core.fsmonitor       GIT_CONFIG_VALUE_3=false
GIT_CONFIG_KEY_4=core.autocrlf        GIT_CONFIG_VALUE_4=false
GIT_CONFIG_KEY_5=core.longpaths       GIT_CONFIG_VALUE_5=true

From GitClient.RunAsync (GitClient.cs:141-164). The token never reaches a command line or .git/config. Hooks and fsmonitor are off, so code that the agent writes into the clone does not run when the runner calls git. Commits use -c user.name/user.email from git.userName/userEmail and --no-verify (l.97-99).

Dependencies

  • Uses: Configuration/RunnerConfig, and Core types (GbIssue, JobRequest, AsciiSanitizer, BotComments, Text).
  • Used by: all Jobs and the Hosting classes.
  • Tests: GitBucketClientTests (7, with a fake HTTP handler), GitWorkspaceTests (5, real git on a file:// bare repo), ProcessRunnerTests (3). LabelSetup, AgentInstaller and CopilotSelfTest have no test (finding F8).
Gotcha Git object files are read-only on Windows, so a plain Directory.Delete fails. Always use FileSystem.DeleteDirectory, which clears the attributes first (FileSystem.cs:9-23).
Warning SendAsync returns default! for an empty reply body (GitBucketClient.cs:176). For a record type that is null, so a surprising empty reply shows up later as a NullReferenceException (finding F15).
