Implement and AgentSession

Workflow 2: Copilot writes code on a branch and checks itself; the runner re-checks build, test and lint, sends failures back for fix rounds, then pushes and opens the PR.

On this page:PurposeComponentsFlow 1: the whole implement jobFlow 2: the agent session and fix roundsBusiness rules and edge casesDependencies

Purpose

A human adds ai-implement to a simple, analysed issue (or a sub-issue). ImplementIssueJob prepares a branch and a plan.md, and hands the work to AgentSession. The agent goes through five stages by itself: understand, change and test, verify, review and simplify (with the read-only code-reviewer subagent), and write PR_BODY.md. The runner does not trust the agent's claim. It runs build, test and lint again, checks PR_BODY.md, and sends the problems back for up to implement.maxFixRounds follow-up rounds. Then it commits, pushes (never forced) and opens the PR. The agent never runs git and never merges.

AgentSession is shared with the review fix job (PR review and review fix).

Flow 1: the whole implement job

  1. Choose branches and plan. A sub-issue builds on feat/issue-P into ai/issue-P-K and its plan is its own body. A normal issue builds on the default branch into ai/issue-N and its plan is the latest SPEC block (l.46-70). Working on the base branch itself is refused (l.69-70).
  2. Order check for sub-issues. The previous sub-issue must be done. The list comes from the parent's hidden SUBISSUES marker (l.168-180).
  3. No second PR. If an open PR from the branch to the base exists, the job only fixes the labels and says so (l.72-81).
  4. Continue saved work. If the remote branch has commits that the base lacks, all of them must have the runner's author email. Otherwise a person may be working there, and the job fails (l.83-96).
  5. Run the agent session (next flow), then commit and push first, judge size second: too big or not, the code is on the branch (l.134-137).
  6. Size limit. More than maxChangedFiles files or maxDiffLines changed lines: no PR, a comment explains, labels are removed (l.138-149).
  7. Open the PR. The title gets [WIP - checks failing] when a check still fails. The body is the agent's PR_BODY.md plus the runner's check report and rounds, ending with Closes #N (l.151-155, 189-198).

Flow 2: the agent session and fix rounds

When does another fix round start?

  1. Setup. commands.setup runs first, because the work folder was cleaned and node_modules or .venv are gone. A failing setup fails the job (l.60-65).
  2. Guard. After every Copilot run and every check, the hash of .git/config is compared with the start value. If it changed, the clone is deleted and the job fails, so nothing is pushed (l.67-77).
  3. Checks. Build first. If the build fails, test and lint are skipped because they would repeat its errors. Otherwise test and lint both run, so one fix round gets every failure (l.103-117).
  4. Fix input. fix.md lists failing commands with the last 3000 characters of output and the PR_BODY.md problems. diff.patch holds everything changed so far (l.156-165).
  5. A failed fix round (quota, timeout) stops the loop but the PR is still opened from what exists. Only a round 1 Copilot failure fails the job (l.123-124, 166-171).

Dependencies

  • Uses: IGitBucketClient, IWorkspace, IGitClient, ICopilotRunner, IProcessRunner, IStateStore; Core: ImplementGate, PrBodyParser, ShellPermissions, ContextBuilder, SubIssueBody.
  • Used by: JobWorker. The PR it opens is picked up by PR review (branch ai/*, author = the bot).
  • Tests: ImplementIssueJobTests (21), ImplementCoreTests (22), GuardRailTests (8).
Warning The setup, build, test and lint commands run code the agent wrote, as you, with your files visible. The .git/config guard and the missing tokens limit the damage but it is not a sandbox (finding F2).
Gotcha A "fix round" here means an extra Copilot run started by the runner after its own checks failed. It is not the same as a "review fix", which is a reply to an @ai comment on a PR. They share AgentSession and the maxFixRounds setting.
Note Each fix round costs at least one premium request. With maxFixRounds: 0 the PR is opened as WIP at once when a check fails (repos.yml:45-47).
