Analysis and breakdown

Workflows 1 and 1b: Copilot analyses an issue in rounds until it is ready, then a complex issue is split into ordered sub-issues that are built one by one.

On this page:PurposeComponentsFlow 1: one analysis roundFlow 2: breakdown into sub-issuesFlow 3: building the sub-issues in orderBusiness rules and edge casesDependencies

Purpose

Before any code is written, an issue needs to be clear. Workflow 1 lets a read-only Copilot agent (grill-issue) read the issue and the code, ask up to 7 questions, list assumptions, guess whether the work is simple or complex, and, when no question is left, write a SPEC. Workflow 1b takes an approved complex issue and turns it into ordered sub-issues on a feature branch, then starts them one after the other. Workflow 1b makes no Copilot call, because the analysis already contains the breakdown.

Flow 1: one analysis round

  1. Re-plan: LoadIssueAsync reads the issue and comments and calls PlanIssue again. If the answer is not AnalyzeIssue, the job ends quietly (l.28-30).
  2. Count rounds with AtAiThread. At the limit the job fails on purpose, so the bot explains that humans should clarify in a call (l.33-38).
  3. Clean checkout of the default branch, then context.md with all comments (l.40-44).
  4. Copilot runs read-only with the prompt Analyze the issue in context.md ... (l.19-20, 46-51).
  5. Strict checks: the ANALYSIS block must exist, Status and Complexity must use the fixed words, and a ready status also requires a SPEC block (l.54-56).
  6. Post: analysis comment, label changes, SPEC comment. Finally the local cursor moves to the newest comment id read (l.58-64).

Flow 2: breakdown into sub-issues

  1. If the labels are wrong the job explains and removes ai-breakdown (l.29-34).
  2. BreakdownParser.Parse reads the table from the latest analysis block. Errors are specific: not 5 cells, rows not numbered 1..n, a dependency on a later row, empty title or scope, missing Shared contract: (BreakdownParser.cs:22-57).
  3. The feature branch feat/issue-N is created from the default branch by pushing origin/<default> to it, unless it exists (l.42-49).
  4. Sub-issue labels: ai (the scope label) and ai:sub-issue; plus ai:ready and ai:simple unless the row is a [developer] row; plus ai-implement on row 1 only when autoStartFirstSubIssue is true (l.71-76).
  5. The parent gets a comment that lists the sub-issues and ends with <!-- SUBISSUES: n1,n2,... --> (l.85-100). This is how every later step finds the order.

Flow 3: building the sub-issues in order

The final PR body lists the sub-issue PRs and ends with Closes #N (SequenceSubIssuesJob.cs:55-78). A sub-issue closed without a runner PR is listed as "closed without a runner PR".

Business rules and edge cases

  • Maximum 7 questions and fixed headings are rules for the agent, in agents/grill-issue.agent.md. The runner only checks Status and Complexity.
  • Simple means up to 5 files of production code, a clear requirement, similar code already exists, no migration and no external change. Test files, snapshots, fixtures, mocks, docs and lock files do not count.
  • Breakdown rows must themselves be simple. A row the agent cannot make simple starts with [developer]. A human builds it, and the sequencer waits for the human (SubIssueSequencer.cs:32-33).
  • Round limit limits.maxAnalysisRounds (default 5) counts bot replies carrying the ANALYSIS marker.
  • The first sub-issue is always started by a human (or by autoStartFirstSubIssue). The sequencer returns Wait for sub-issue 1 (SubIssueSequencer.cs:26-27).
  • Existing sub-issues are matched by their body (Parent and Order lines), not by title, and only among open issues with ai:sub-issue (BreakdownIssueJob.cs:52-58).

Dependencies

  • Uses: IGitBucketClient, IWorkspace, ICopilotRunner (analysis only), IGitClient (breakdown), IStateStore, and the Core parsers.
  • Used by: JobWorker through JobFactory. The result feeds implement (SPEC and sub-issue bodies become plan.md) and review (linked analysis and SPEC).
  • Tests: AnalyzeAndBreakdownJobTests (11), ParserTests, SubIssueSequencerTests, ReviewAndSequenceJobTests.
