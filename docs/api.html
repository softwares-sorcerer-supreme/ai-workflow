CLI and API

ai-runner has no HTTP API of its own. Its interfaces are the command line, the GitBucket REST calls it makes, and the way it starts Copilot.

On this page:Command-line modesGitBucket REST callsHow Copilot is startedAgent input and output contract
Note There is no server API to document. The runner opens no port. This page covers the three interfaces that exist: (1) the command-line modes, (2) the GitBucket /api/v3 endpoints the runner calls, and (3) the copilot command line it builds.

GitBucket REST calls

All calls go through IGitBucketClient (Infrastructure/GitBucketClient.cs:12-36). The base address is {baseUrl}/api/v3/, the header is Authorization: token <token>, and the timeout is 30 seconds (Program.cs:36-45). repo is always owner/name. JSON uses snake_case (GitBucketClient.cs:47-50).

Request and response examples

Add a comment

POST /api/v3/repos/james/mbhanalytics/issues/52/comments
Authorization: token <token>
Content-Type: application/json

{ "body": "<!-- ai-runner -->\n**[ai-runner]**\n\n<!-- ANALYSIS_START -->\n## AI analysis - round 1\n...\n<!-- ANALYSIS_END -->\n<!-- ai-runner:context-upto=1234 -->" }

WithMarker prepends the first two lines when the body does not already contain the marker (GitBucketClient.cs:136-142).

Open a pull request

POST /api/v3/repos/james/mbhanalytics/pulls

{ "title": "Add export", "head": "ai/issue-52", "base": "main", "body": "...\n\nCloses #52" }

GitBucket's create reply cannot be read as a GbPull. Only number is trusted, and the PR is read back with GET pulls/{n} (GitBucketClient.cs:124-132).

Add labels

POST /api/v3/repos/james/mbhanalytics/issues/52/labels

["ai:ready", "ai:simple"]

How Copilot is started

copilot -p "<prompt>" -s --agent <agent> [--model <m>]
        --allow-tool=<t> ... --deny-tool=<t> ... [--share <file>] <copilot.extraArgs>

Built in CopilotRunner.RunAsync (Infrastructure/CopilotRunner.cs:26-44). -s prints only the final answer, so the full session is exported with --share for the implement and fix jobs. The child process has no GitBucket or GitHub tokens.

JobAgentAllowed toolsDenied tools
AnalyzeIssueJobgrill-issue-write, shell
ReviewPullRequestJobpr-review-write, shell
ImplementIssueJobimplement-issuewrite, shell(tool:*) for the tool of each setup/build/test/lint command, plus commands.allowShellshell(git), shell(git:*), write(.ai-workflow)
FixReviewJobfix-reviewsame as implementsame as implement

Allowed tools come from AgentSession.AllowTools and ShellPermissions.For (AgentSession.cs:195-200, ShellPermissions.cs:27-47). For example dotnet build X.sln becomes shell(dotnet:*). Shells and launchers such as powershell, bash, env keep the exact command. git never gets a permission. In Copilot CLI a deny rule wins over an allow rule, so git stays blocked even if allowShell says otherwise (AgentSession.cs:199).

Warning The deny rule write(.ai-workflow) is in the code, but whether Copilot applies it to files inside that folder is marked "unconfirmed" in CLAUDE.md. The runner re-copies the templates on every run and never commits the folder as a second line of defence (Workspace.cs:58).
