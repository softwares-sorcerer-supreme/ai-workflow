Things the code already does well

  • Strict parsing before any write: a bad agent answer is never half-applied (AnalyzeIssueJob.cs:53-62).
  • Work is never lost: implement pushes partial or oversized work to the branch before it fails (ImplementIssueJob.cs:122-136).
  • The push is never forced, and a moved branch ends in a refusal or a clear failure (GitClient.cs:101-102, FixReviewJob.cs:83-87).
  • Secrets: tokens stripped from child processes, git auth through environment variables, .git/config hash guard (ProcessRunner.cs:51-80, AgentSession.cs:67-77).
  • Duplicate and late jobs are harmless because every job plans again on fresh data (JobSupport.cs:26-34).

Open questions

Things that could not be confirmed from the code:

  1. Does write(.ai-workflow) block writes to files inside the folder? CLAUDE.md says this is unconfirmed.
  2. What exact words does Copilot CLI print when the premium quota is used up? CopilotRunner.LooksLikeQuotaError is a guess.
  3. Which GitBucket version runs the server? The code has several version fallbacks: refs/pull/* may be missing, merged may be missing, labels may be ignored on issue create (Labels.cs:47-48, GitBucketModels.cs:70, BreakdownIssueJob.cs:80).
  4. What is Jenkins' role? The design document name mentions Jenkins. No Jenkins file or reference exists in this repo, and the design document (one folder above the repo) was not read.
  5. The test suite was not run for these docs. The count of 177 test methods comes from searching for [Fact] and [Theory].
  6. Uncommitted work. These docs describe the working tree on top of commit 4910fce. Eight tracked files are modified (CLAUDE.md, JobPlanner.cs, Labels.cs, AnalyzeIssueJob.cs, FixReviewJob.cs and three test files), and Core/AtAiThread.cs, Core/BotComments.cs, CONTEXT.md and AtAiThreadTests.cs are untracked.
