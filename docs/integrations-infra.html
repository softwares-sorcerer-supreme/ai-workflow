Deployment

There is no server deployment. The runner is started by hand (dotnet run) or as a long-running console process on a developer laptop with VPN access. There is no Dockerfile, no service definition and no pipeline in the repository. The README notes that "each runner pointed at the repo" reviews a PR again with scope: all, so more than one laptop can run it (README.md "Onboard a repo"). That is why review scope defaults to scoped (RunnerConfig.cs:172-176).

Open question The design document's file name mentions Jenkins ("GitBucket + Jenkins + Copilot CLI", CLAUDE.md). No Jenkins file or reference exists in this repository, and the design document was not available. Whether Jenkins builds the product repos is unknown (see Open questions).

Queue and event flow

There is no message broker. The "queue" is a Channel<long> of job ids in memory plus the jobs table in SQLite, so a restart loses nothing (JobQueue.cs:7-13).

The only event-like chain is sub-issue sequencing. It is poll-driven, not event-driven: a merged PR is noticed by the next poll.
