What the system does

ai-runner is a .NET 10 Worker Service that runs on a developer's laptop (it needs the company VPN and internet). It polls a GitBucket server through its GitHub-compatible REST API (/api/v3), and runs the GitHub Copilot CLI (copilot -p --agent ...) as a child process when an issue or pull request needs AI work. It then writes the results back to GitBucket as comments, labels, branches and pull requests (src/AiRunner/Program.cs:7-12, CLAUDE.md "What this is").

The users are the developers of the repositories listed in repos.yml. They do not call the runner. They drive it with normal GitBucket actions: put the label ai on an issue, answer the bot's questions and write @ai, add ai-implement or ai-breakdown, or comment @ai on a pull request. A human always merges. The runner never merges.

Note Nothing runs in the cloud on our side. The runner is a normal process on the laptop. It uses the developer's own Copilot login and its own GitBucket token. The design document lives one folder above the repo (see CLAUDE.md); it is outside this repository and was not read for these docs.

Main features

Issue analysis

Copilot reads the issue and the code, asks up to 7 questions, lists assumptions, guesses complexity and writes a SPEC when ready.

Workflow 1

Breakdown into sub-issues

A complex issue becomes ordered sub-issues on a feature branch. The next one starts when the previous PR is merged.

Workflow 1b

Implementation

Copilot writes code on ai/issue-N. The runner re-runs build, test and lint, sends failures back, then opens the PR.

Workflow 2

PR review

One review comment per PR, updated in place on each new head commit. It is advice, never a block.

Workflow 3

Review fix

An @ai comment on a PR makes Copilot change the PR branch and reply point by point.

Workflow 3b

Cost and safety controls

One job at a time, per-job timeouts, size limits, round limits, a cost log, and a guard on .git/config.
