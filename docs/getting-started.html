Getting started

Install, configure, run the tests and run the runner on your laptop. Includes every setting and secret the runner reads.

On this page:PrerequisitesInstall and configureRunRun the tests and buildConfiguration referenceWhat runs where

Prerequisites

  • .NET 10 SDK (the projects target net10.0, AiRunner.csproj:4).
  • git on the PATH. The runner calls it for every clone, fetch, commit and push.
  • GitHub Copilot CLI installed and logged in (copilot then /login). The runner starts it as copilot -p .... On Windows you may need the full path in copilot.command (see the comment at repos.yml:9).
  • VPN access to the GitBucket server and internet for the Copilot service (README.md).
  • A GitBucket access token of the bot user (an account that can read and write the target repos).
Warning The runner spends real Copilot premium requests and writes to the real GitBucket. For development, only the tests and --once --dry-run are free and safe. CLAUDE.md asks AI assistants never to run --copilot-test, --once without --dry-run, or the loop.

Install and configure

  1. Clone the repository and open a PowerShell in its root.
  2. Store the token in user secrets (it is never written into repos.yml): 
    dotnet user-secrets set GitBucket:Token <ai-bot token> --project src/AiRunner
# only if git over HTTP needs a password other than the token:
dotnet user-secrets set GitBucket:GitPassword <password> --project src/AiRunner
  3. Edit repos.yml: set gitBucket.baseUrl, copilot.command, and one entry under repos: for every repository (see the next section).
  4. Copy onboarding/AGENTS.md to the root of each product repo and fill it in (build and test commands, folder map, conventions, "Never edit" folders). The agents read it first.
  5. Create the workflow labels in every configured repo: 
    dotnet run --project src/AiRunner -- --setup-labels

Run

CommandWhat it doesCost / risk
dotnet run --project src/AiRunner -- --once --dry-runPoll once, print what would be queued, change nothing.safe reads GitBucket only
dotnet run --project src/AiRunner -- --copilot-testStart Copilot as a child process, with and without a task file, and show the output.premium requests
dotnet run --project src/AiRunner -- --oncePoll once, run the queued jobs, exit.writes to GitBucket
dotnet run --project src/AiRunnerNormal mode: poll every pollIntervalSeconds and run jobs until Ctrl+C.writes to GitBucket

The modes are chosen in Program.cs:13-17 and Program.cs:71-113. The runner finds repos.yml in the current folder or a parent folder, or from --config <path> (Program.cs:121-130). At startup (not in dry-run) it copies agents/ and skills/ to ~/.copilot/ (AgentInstaller.cs:12-24) and deletes job log folders older than logRetentionDays (JobLog.cs:51-58).

First-run order

Run the tests and build

dotnet build ai-workflow.slnx
dotnet test ai-workflow.slnx

The tests need no network, no VPN and no Copilot. GitBucket, Copilot and processes are faked (tests/AiRunner.Tests/Fakes/). GitWorkspaceTests uses the real git against a file:// bare repository. There are 177 [Fact]/[Theory] methods in 16 test files (counted with grep; the suite was not executed for these docs).

Note There is no CI/CD pipeline file in this repository (no .github/, Jenkinsfile, Dockerfile). The only build is the local dotnet build.

Gotcha Do not repeat a top-level key in repos.yml. YAML duplicates are accepted without a warning and the last block wins. A second copilot: block once dropped --disable-builtin-mcps and the 45-minute timeout (finding F1, now fixed).

What runs where

The runner opens no listening port. All traffic is outgoing: REST and git to GitBucket, and Copilot's own calls to the Copilot service.
