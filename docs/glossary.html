How the @ai conversation works

These terms come from CONTEXT.md and Core/AtAiThread.cs. The words in the first column are the preferred names. Use them in code and comments.

TermMeaningWhere in code
Bot commentA comment the runner posted itself, found again by its hidden marker.BotComments.cs:13-21
BlockA marked section inside a bot comment, one per kind: analysis, spec, review, review fix.Markers.cs:8-40
ThreadThe bot comments of one block kind on one issue or PR, with the human comments around them.AtAiThread.cs:13-30
TriggerThe newest human comment that mentions @ai and that no reply has answered yet.AtAiThread.cs:50-51
ReplyA bot comment that answers a trigger: an analysis (one round) or a review fix.AtAiThread.cs:63-67
Read-up-toThe newest comment id a job had read when it posted its reply. Stored in the context-upto tag.AtAiThread.cs:44, 70-75
Answered-up-toThe point after which comments are new: the later of the last reply's read-up-to and the local cursor.AtAiThread.cs:27, 47
Local cursorThe newest @ai comment the runner's database says was handled. It covers a job that failed before it could reply.SqliteStateStore.cs:98-106
RoundOne analysis reply on an issue. Numbered and capped by limits.maxAnalysisRounds.AnalyzeIssueJob.cs:33-38
Review fixOne reply on a PR after the agent changed the PR's branch to answer an @ai comment. Capped by limits.maxReviewFixes.FixReviewJob.cs

Domain terms

TermMeaning
ai-runnerThe .NET worker in src/AiRunner. Also the visible tag **[ai-runner]** on its comments.
GitBucketThe self-hosted Git server with a GitHub-compatible API (/api/v3) that the team uses.
Copilot CLIGitHub's command-line agent. The runner starts it as copilot -p.
Premium requestThe unit of Copilot quota. Every Copilot run (including each fix round) costs at least one.
AgentA Copilot agent definition in agents/*.agent.md: grill-issue, implement-issue, fix-review, pr-review, code-reviewer.
SkillA reusable instruction file in skills/*/SKILL.md: grill-me, implement-checklist, review-checklist.
TemplateA fixed layout in templates/ that an agent fills in and a Core parser checks.
AGENTS.mdA file in each product repo that tells the agent the build and test commands, the folder map and what never to edit. Starting point: onboarding/AGENTS.md.
MCPModel Context Protocol servers. --disable-builtin-mcps turns the built-in ones off for the agent.
Scope labelThe label (ai) that makes the runner look at an issue. Also opts a PR into review.
Scoped reviewReview mode where only PRs labelled ai, or opened by the runner from ai/* or feat/issue-*, are reviewed (review.scope: scoped).
JobOne unit of work (JobRequest) with a key Type:Repo#Number. Six types in JobType.
Plan / PlanDecisionThe planner's answer for one issue or PR: a job to run, or the reason to skip.
Routine decisionA plan made on every poll (sequencing) that is not worth an info log line.
NeedsCommentsThe plan depends on comments that were not read yet. The poller then fetches them if the issue changed.
Fingerprintupdated_at plus the sorted labels of an issue. Unchanged = not read again.
Quiet outcomeA job result that means "nothing was needed". The job row and log folder are deleted.
Re-planEvery job calls JobPlanner again on fresh data before it does anything.
AnalysisCopilot's written answer to an issue: questions, assumptions, plan, complexity (templates/analysis.md).
Statusquestions-open or ready. Set by the agent in the analysis.
Complexitysimple or complex. Simple: up to 5 files of production code, no migration, no external change.
SPECThe final plan posted when the status is ready: goal, scope, acceptance criteria, technical plan, shared contract (templates/spec.md).
Acceptance criteriaGiven / When / Then statements. The implement agent must cover each one.
BreakdownThe table of ordered sub-tasks for a complex issue (| # | Title | Scope | Touches | Depends on |).
Shared contractThe exact names (types, endpoints, enums) every sub-task must use. Copied into each sub-issue.
Parent / sub-issueA complex issue (ai:parent) and the issues the breakdown created from it (ai:sub-issue).
Feature branchfeat/issue-N: where sub-issue PRs are merged. A final PR brings it to the default branch.
Work branchai/issue-N (simple issue) or ai/issue-N-K (sub-issue K of parent N).
[developer]Title prefix in a breakdown row: the agent could not make this part simple, so a human builds it.
[skip-ai]PR title prefix that excludes the PR from review and fix (JobPlanner.cs:13, 109).
StagesThe five steps an implement or fix agent goes through itself: understand, change and test, verify, review and simplify, write the output file.
Fix roundAn extra Copilot run started by the runner when its own checks fail or the output file is incomplete. Limited by implement.maxFixRounds. Not the same as a "review fix".
PR_BODY.mdThe PR description the implement agent writes (templates/pr-body.md).
REPLY.mdThe reply the fix-review agent writes (templates/review-reply.md).
fix.md, diff.patchInput of a fix round: failing checks and the diff so far.
WIP PRA PR opened with [WIP - checks failing] in its title because build, test or lint still fails.
Guard railA protection that reduces risk but is not a security boundary, for example the shell permission patterns.
Dry run--dry-run: print decisions, change nothing.
Work folderwork/<owner>/<name>: the persistent clone, reset before every job.
Workflow numbers1 analysis, 1b breakdown, 2 implement, 3 review, 3b review fix, 4 GitHub fallback (not built).
VPNThe company network access that the laptop needs to reach GitBucket.
POCO"Plain old CLR object": the classes in Configuration/RunnerConfig.cs that hold repos.yml.
NU1903NuGet vulnerability warning for the native SQLite package. The reason SQLitePCLRaw.lib.e_sqlite3 is pinned (AiRunner.csproj:13).
